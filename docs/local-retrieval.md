# Локальный поиск по базе знаний

## Нужны ли embeddings и reranker?

Для RAG да: embeddings позволяют искать парафразы и семантически похожие вопросы, а не только совпадающие слова. Reranker не обязателен для первой версии; он может улучшить порядок уже найденных кандидатов, но не компенсирует плохой recall.

## Локальные модели LM Studio

- Embeddings: `text-embedding-qwen3-embedding-0.6b` (уже установлен в LM Studio, около 639 MB).
- Reranking: `qwen/qwen3.5-4b` как локальный LLM reranker, потому что отдельная reranker-модель не установлена. Он получает только candidates и возвращает их порядок.

Подключение через локальный OpenAI-compatible API, без отправки текстов документов внешнему провайдеру.

## Фактическая проверка на текущих 4 секциях KB

При пороге cosine 0.50:

| Вопрос | Лучший результат | Similarity |
|---|---|---:|
| Какой срок возврата товара? | returns.md / Срок | 0.661 |
| Можно ли вернуть товар с нарушенной упаковкой? | returns.md / Исключения | 0.661 |
| Сколько занимает доставка заказа? | delivery.md / Срок | 0.509 |
| Какие документы нужны для полёта на Марс? | нет результатов | ниже порога |

Порог пока предварительный: проверено лишь четыре коротких секции и несколько ручных запросов. В текущем smoke запросе reranker-кандидат был один, так что его влияние на порядок не доказано. Для оценки добавим более крупный датасет и измерим Recall@k/MRR до и после reranking.

## Запуск

```bash
lms load text-embedding-qwen3-embedding-0.6b -y
lms load qwen/qwen3.5-4b -y
lms server start --port 1234
uv run pytest -q tests/test_embeddings.py tests/test_local_retrieval.py
```

## Политика fallback

- Если semantic search не вернул chunks — LLM генерации не будет.
- Если reranker недоступен или вернул недействительные индексы, приложение должно оставить исходный retrieval rank.
- Reranker не является источником фактов и не может добавлять chunks.
